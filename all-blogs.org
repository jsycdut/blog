=学习emacs的要点=
/1. 知道你想要的效果对应着emacs的什么功能/
/2. 会调用功能对应的命令/
/3. 会给对应的命令写适合你用的快捷键/

emacs需要知道的两个关键概念，mode和mode map

emacs的UI概念
Frame：独立的，可与用户交互的emacs UI整体。
tab：位于同一个Frame中，并行存在的多个独立交互页面，但是每次只能选中其中一个页面进行操作
window：位于一个Frame或者其下的tab中的，一个或者多个可以被独立操作的区域的集合
buffer：用户编辑内容，展示内容的区域


emacs的mode概念
emacs中的mode是针对每一个独立的buffer的，包含了 *major mode* 和 *minor mode* 两种模式，以及展示当前模式信息的 *模式行* 信息。

任何一个编辑器，最基础的功能肯定是：我们在其中输入字符集合的动作就像用钢笔在纸质笔记本上写字一样，但是，这个要求太低了，我们肯定希望编辑器为我们带来更多的东西。比如
如果我输入的一段折叠过的json文本，那么我希望emacs给我把它美化成我眼睛喜欢的格式
如果我输入的是一段java，cpp，python，JavaScript代码，我希望它给我高亮其中的关键字，函数定义等
在emacs中，上面提到的功能，可以通过设置对应的 *major mode* 来实现，这些 *major mode* ，或者 *minor mode* ，本质上都是一些功能的集合，如果我们需要某些功能，需要找到对应的mode，将其打开，然后就可以通过调用命令的方式来执行对应的功能。 *major mode* 是一个buffer的主要模式，只能有一个，提供与这个buffer内容所属类型的最核心的功能， *minor mode* 是一个buffer的辅助模式，提供着辅助功能，可以有多个。

如果要查看一个buffer有哪些mode，可以通过 ~C-h m~ 来查看，它会提供给你这个buffer中开启了的所有mode的信息，并且告诉你你有哪些快捷键以及对应的命令可用，是非常实用的一个功能。

emacs中的 *mode map*

在我知道我要做什么的时候，快捷键用于加速我的行为得到结果。 emacs中的key bindingds就是快捷键， ~C-h-b~ 可以查看当前buffer所有的快捷键（按照优先级排序），一个buffer有不同的mode， *mode map* 就是在对应mode下面的快捷键， 名字一般是 ~模式名-mode-map~ 。快捷键是有优先级的，顺序是

1. minor mode。在开启的minor mode中一个个查，顺序就是你 ~C-h-b~ 的里面出现的那个顺序
2. major mode。主模式下面定义的快捷键
3. global map。兜底，一般设置的全局可用的

#+begin_src elisp

  ;; 给特定mode绑定快捷键，使用define-key函数
  (define-key python-mode-map (kbd "<f5>") '我要执行的函数)

  ;; 给特定mode绑定快捷键，使用use-package定义mode快捷键
  (use-package python
    :bind (:map python-mode-map
		("<f5>" . 我要执行的函数)))

  ;; 全局绑定
  (global-set-key (kbd "C-c l") '我要执行的函数)
#+end_src

*** Emacs如何全局替换
依赖consult-ripgrrep + embark
1. consult-ripgrep进行搜索
2. 在搜索结果中，调用embark-act，进入embark-export
3. 在embark-export跳出的缓冲区中，命令：wgerp-change-to-wgrep-mode，这样才能写这个buffer，在开始之前，会告诉你保存和放弃更改的快捷键，记住即可
4. 命令：query-replace，然后依次输入要替换的源对象RET，目标对象RET，然后系统会逐个询问你是否替换，你y/n进行选择，搞完之后用3的保存和放弃结束动作

*** 我的理解
基于时间线，我整理如下：
| 概念   | 相关时间 | 相关人物/机构                           | 我的理解                                                       |
| UNIX   |    1969 | Dennis Ritchie/Ken Thompson/Bell Labs | 现代操作系统的基石，初代计算机黑客的天才作品                          |
| 类UNIX |    197x | 各种unix衍生出来的系统                   | UNIX很优秀，有商业价值和学术价值，商界和学术界都基于UNIX搞出来自己的版本 |
| BSD    |    197x | Berkeley Software Distribution        | 类UNIX中的学术派版本，属于加利福尼亚大学伯克利分校                    |
| POSIX  |    1988 | IEEE                                  | 类UNIX版本太多了，难以在各种物理机上面都正常运行，所以IEEE搞了一个标准   |
| Linux  |    1991 | Linus Torvalds                        | 基于UNIX的一个实现，借鉴其思想，但是自行实现其功能，一般指的是系统内核    |
| OS X   |         |                                       |                                                               |

UNIX是商业机构的作品，虽然他来自于两位天才黑客，但UNIX是两位大佬是在给贝尔实验室打工的时候写出来的，所以UNIX属于贝尔实验室这个商业机构，一开始管控没有那么严格，UNIX在外部世界（商业+学术）开花，出现了各种基于UNIX系统（类UNIX系统），后面各种UNIX五花八门，IEEE作为标准化机构，就搞出来一个POSIX标准，让大家的UNIX实现都有规范可以遵循，但是标准终归是标准，又没有强制所有系统必须按照这个标准实现，各种类UNIX系统也仅仅是将POSIX作为参考。

能称之为UNIX系统的，都是商业上的系统，比如\\
OS X，属于Apple公司，一般装备在MacBook系列笔记本电脑上，通过了UNIX 03认证\\
AIX，属于IBM公司，基于UNIX System V标准的商业版操作系统。它专门运行在IBM专有的Power系列芯片服务器（如Power Systems、RS/6000）上，以高度的安全性、可靠性、强大的扩展性以及对关键任务（如银行、大型企业数据库）的支持而闻名\\
Solaris，属于Sun Microsysems的商业操作系统\\
HP-UX，属于HP（惠普）的UNIX System V标准的商业版操作系统

其他的，都可以称之为类UNIX系统，而类UNIX系统中的两大佼佼者，分别是BSD和Linux。BSD来自学术界，目前划分出了Free BSD（最流行，注重稳定性和性能），Open BSD（注重安全）和NetBSD（注重可移植性）三个方向，Linux则是现在服务端系统的王者，它起源于Fuck Nvidia的顶尖黑客Linus Torvalds，现在掌控着大部分的服务端系统市场，是名副其实的类Unix系统之王，当然Linux一般我们指的是内核部分，是最硬核的部分，然而我们平常接触到的一般是称为Linux发行版的操作系统，比如Ubuntu，Cent OS，Arch Linux，Kylin等，它是Linux内核 + 一系列用户交互软件的组合，这些用户软件包括Bash、GCC、包管理器、桌面管理系统等。

在类Unix系统中，top命令可以查看系统里面的进程情况，很多时候，我们需要对进程做一些筛选，比如
1. 谁占用CPU最高，谁占用内存最高
2. 进程启动参数，究竟启动的时候传入了哪些参数

top在所有的linux发行版和OS X上面都有，如果是docker容器中，也有类似的docker top命令可供使用，top是最基础的工具，与之相比，提高了使用便利性的工具还包括[[https://htop.dev/][htop]]和[[https://terminaltrove.com/btop/][btop]]。

htop支持cpu、内存可视化的展示，进程关系的树形展示，按照内存、cpu等对cpu排序，方便的kill指令，使得你只需要按几个键就可以达到你的目的，你只需要花费10分钟，看一下界面布局，然后按F1查看一下帮助信息，并且把界面上的F1-F10全部按一遍，就可以学会它。而btop则更加华丽并且易用，你看到界面中的红色表示的内容，比如1~4，或者对应的字母，按一下对应的内容，也就很自然的学会了，这使得你无需先去看一下help才能操作，btop的help菜单更多是针对UI展示内容的调节，没有太多需要学习的。

使用htop和btop更多是在偷懒的动作，在我们自己的电脑上，毫无疑问这个东西是方便并且看起来非常fancy的，但是一旦到了服务器的世界，更多的还是top这种最返璞归真的工具，所以，让我们回到top上来。

注意，linux的top和OS X展示的top的内容不一样。
在OS X上，man top命令的展示内容是 top – display sorted information about processes，Linux上是top - display Linux processes。

在Linux上，top来自procps软件包，而OS X上top则来自内核Darwin，要溯源到BSD，所以两者根本不是一个体系，展示内容不同，使用的语法不同等就可以理解了，而上面提到的htop、btop就没有这个问题，其实按我的理解，htop btop已经是TUI程序了，而非单独的命令行工具。

我们用包(package)来组织多个go代码源文件，然后使用模块（module）组织多个包，让多个包可以以一个统一的身份进行发布，所以我们可以把go项目看成源文件、包、模块的三级结构。具体上可以理解为
go文件就是源代码纯文本文件，一个文件夹下面的多个go文件我们说们属于同一个包，这个文件夹下面的go文件的第一行都是package xxx（xxx一般是这个go文件所在的文件夹的名字），包里面任意一个源文件中定义的函数、类型、变量、常量等对同一包中的其他源文件都可见。
模块(module)是有关联的go包的集合，它们在一起被发布、版本化和分发。模块可以直接从版本控制仓库(github gitlab)或者模块代理服务器(GOPROXY指定的地址)下载。
 go语言的包存放在文件夹里面，文件夹可以嵌套，每个深度的文件夹里面都可以声明自己的包，但是这些包不存在任何嵌套关系，它不像java里面那种com.xxx.x.y.z这样的存在深度以及继承关系的，go语言里面的包都是平级的，没有等级和继承关系。go包建议包名和所在的文件夹的名字一样，除非你是main包，一个文件夹下面也不允许多个go包的存在，一个文件夹就一个包，这里也存在一个例外，那就是_test包，它是用来搞测试的，但是它的名字也需要被叫做 ~被测试的报名_test~ ，也不能乱起名。

 在go语言的世界里面，大家都是以 ~模块~ 的身份来行走江湖的，模块的go.mod文件，就声明了我是谁，我需要至少什么版本的go，我需要哪些其他模块来支持我的工作之类的信息，它对标记一个模块至关重要，没有这个文件，你就没有在这个世界 的通行证。

     void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }

    // 选择排序是把数组划分为两段，左边是已排序列表，右边是未排序列表，每次从未排序列表里面选最小的一个放到左边已排序列表的末尾
    // 关键是要理解这两段列表
    void selectionSort(int[] nums) {
        int len = nums.length;
        for (int i = 0; i < len; i++) {
            int min = i;
            for (int j = i; j < len; j++) {
                if (nums[j] < nums[min]) {
                    min = j;
                }
            }
            swap(nums, i, min);
        }
    }

    // 冒泡排序模拟的是水中气泡上浮的过程，大泡泡先到水面，小泡泡就要慢点，遵循的是把大泡泡挪到后面
    // 它是从头开始依次比较两个数字，如果两个数字前大后小，则交换，一路比较一路交换，把这里面的最大的数字交换到它的最后
    // 选择排序是前半部分有序，后半部分排序的时候无序
    // 冒泡则是后半部分有序，前半部分无序
    void bubbleSort(int[] nums) {
        int len = nums.length;
        for (int i = 0; i < len ; i++) {
            for (int j = 0; j < len - i - 1; j++) {
                if (nums[j] > nums[j+1]) {
                    swap(nums, j, j+1);
                }
            }
        }
    }

    // 插入排序看起来和选择排序类似，都是左边一个已排序列表，右边一个未排序列表
    // 但是插入排序是从未排序列表里面挑第一个，把它塞入到左边已排序列表中的合适位置
    // 具体来说是从已排序列表末尾的位置开始，一个个的和已排序列表中的比较
    // 已排序列表中比他大的依次往后坐，最终给他腾出一个位置来
    void insertionSort(int[] nums) {
        int len = nums.length;
        for (int i = 1; i < len; i++){
            int key = nums[i];
            int j = i - 1;
            while (j >= 0 && nums[j] > key) {
                swap(nums, j, j+1);
                j--;
            }
            nums[j+1]=key;
        }
    }

    // shellSort是优化版本的插入排序，所以它肯定也有比较、挪位置、交换这几个步骤
    // 但是它是弄了多个步长的，一开始从len/2步长，然后逐渐减半来的，所以它的比较对象、交换对象都是间隔了对应步长的
    // 最后这个步长退化为1，
    void shellSort(int[] nums) {
        int len = nums.length;
        // 初始步长为半个数组长度，然后半数衰减，直到为1（一定能衰减到1，因为整数除2是向下取整的）
        for (int distance = len/2; distance > 0; distance /= 2) {
            for (int i = distance; i < len; i++) {
                for (int j = i - distance; j >= 0; j -= distance) {
                    if (nums[j] <= nums[j+distance]) {
                        break;
                    }
                    swap(nums, j , j+distance);
                }
            }
        }
    }

    // 快速排序是分治思想的提现，另一个分治的排序算法是归并排序
    // 快排的思路是选一个数作为基准数，将整个数组分为两半，左边的值都小于基准数，右边的数都大于基准数，然后对基准数左边和右边分别再重复这个过程
    void quickSort(int[] nums, int low, int hi) {
        if (low >= hi){
            return;
        }

        int pivoitIdx = partition2(nums, low, hi);
        quickSort(nums, low, pivoitIdx - 1);
        quickSort(nums, pivoitIdx + 1, hi);
    }

    int partition(int[] nums,  int low, int high) {
        int pivot = nums[high];
        int i = low;
        while (low < high){
            if (nums[low] < pivot) {
                swap(nums, i, low);
                i++;
            }
            low++;
        }

        swap(nums, i, high);
        return i;
    }

    int partition2(int[] nums, int left, int right) {
        int pivotVal = nums[left];
        int low = left + 1;
        int hi = right;
        while (low <= hi) {
            while (low <= hi && nums[low] <= pivotVal) {
                low++;
            }

            while (low <= hi && nums[hi] >= pivotVal) {
                hi--;
            }

            if (low < hi) {
                swap(nums, low, hi);
                low++;
                hi--;
            }
        }

        swap(nums, hi, left);
        return hi;
    }

    // 归并排序也是分治的思想，把一段区间不断二分，直至无法分割，然后把他们一段段的合并起来，这样就形成了不断增长的有序结构
    // 分，在哪里分
    // 治，分出来的每一段怎么处理
    // 合，如何把每一段的结果拼接起来
    void mergeSort(int[]nums, int l, int r) {
        if (l >= r) {
            return;
        }
        int mid = (l + r) >>> 1;
        mergeSort(nums, l, mid);
        mergeSort(nums, mid+1,r);
        merge(nums, l, mid, r);
    }

    void merge(int[] nums, int l , int mid, int r) {
        int id = 0;
        int i = l;
        int j = mid + 1;
        int[] copy = new int[r -l+1];
        while (i <= mid &&  j <= r) {
            if (nums[i] <= nums[j]) {
                copy[id] = nums[i];
                i++;
            }else {
                copy[id] = nums[j];
                j++;
            }
            id++;
        }

        while (i <= mid){
            copy[id] = nums[i];
            i++;
            id++;
        }

        while (j <= r) {
            copy[id] = nums[j];
            id++;
            j++;
        }

        for(int k = 0;k < copy.length;k++) {
            nums[k+l] = copy[k];
        }
    }

    // 堆化，把一个索引的值，调整到适合它的位置，这里要求它是最大的那个
    void heapify(int[] nums, int endIndex, int point) {
        int max = point;
        int left = 2 * point + 1;
        int right = 2 * point + 2;
        if (left <= endIndex && nums[left] >= nums[max]) {
            max = left;
        }

            max = right;
        }

        if (max != point) {
            swap(nums, point, max);
            heapify(nums, endIndex, max);
        }

        
    }

        }

            swap(nums, 0, i);
            heapify(nums, i-1, 0);

*** maven插件
maven插件是对maven能力的扩展，插件的artifactId命名遵循约定规范，maven官方团队开发的插件命名为 `maven-xx-plugin`，而其他组织开发的插件为 `xx-maven-plugin`，以下是常用的插件信息
| groupId                  | artifactId               | 开发团队 | 用途                                                                                                                                                                         |
| org.apache.maven.plugins | maven-compiler-plugin    | maven    | 控制Java编译行为，常用于配置注解处理器（Lombok和MapStruct），以及指定Java版本，编译参数等                                                                                    |
| org.apache.maven.plugins | maven-resources-plugin   | maven    | 处理src/main/resources/下的内容，做配置文件值替换，把其他资源文件拷贝到指定目录等                                                                                            |
| org.apache.maven.plugins | maven-surefire-plugin    | maven    | 控制单元测试的执行，跳过测试(-DskipTests)，指定运行测试类、配置并行测试并生成测试报告                                                                                        |
| org.apache.maven.plugins | maven-jar-plugin         | maven    | 打普通jar包，控制MANIFEST.MF内容（主类，classpath等），spring-boot项目使用spring-boot-maven-plugin来打包                                                                     |
| org.apache.maven.plugins | maven-dependency-plugin  | maven    | 操作依赖，产用于复制依赖到某个目录，分析哪些依赖没有被使用，查看依赖树用于排查冲突等                                                                                         |
| org.codehaus.mojo        | exec-maven-plugin        | MojoHaus | 在构建过程中执行外部命令或Java主类，常用于调用npm/yarn前端构建，执行数据库迁移脚本，运行代码生成工具                                                                         |
| org.springframework.boot | spring-boot-maven-plugin | Spring   | SpringBoot项目专用，最核心的用途是把项目打成可直接运行的fat jar（含所有依赖），没有这个插件打出来的jar缺少依赖，启动运行报错。另一个场景是mvn spring-boot:run 在本地运行项目 |
